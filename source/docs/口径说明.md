# 口径说明

本文档说明日报中各指标的定义、平台间口径差异，以及归一化过程中的处理规则。
与 Excel 日报「口径说明」Sheet、看板 tooltip 保持一致。

## 一、统一 Schema 与指标定义

所有平台数据归一化到统一 Schema 后再聚合。核心字段：

| 字段 | 说明 |
|---|---|
| `stat_date` | 统计日期（截断到天） |
| `gmv` | 支付金额（口径由各平台适配器声明，见下表） |
| `refund_amount` | 退款金额 |
| `net_amount` | 实际成交额 = `net_amount_formula` 计算结果 |
| `paid_qty` / `order_qty` | 支付件数 / 下单件数 |
| `visitors` / `buyers` | 访客数（UV）/ 支付买家数 |
| `ad_cost` | 推广花费 |

派生指标（聚合层计算，除零返回空值 `—` 而非 0）：

| 指标 | 公式 | 除零处理 |
|---|---|---|
| 退款率 | `refund_amount / gmv` | gmv=0 → — |
| 客单价 | `net_amount / buyers` | buyers=0 → — |
| 件单价 | `net_amount / paid_qty` | paid_qty=0 → — |
| 转化率 | `buyers / visitors` | visitors=0 → — |
| UV 价值 | `net_amount / visitors` | visitors=0 → — |
| 推广 ROI | `net_amount / ad_cost` | ad_cost=0 → — |
| 推广费比 | `ad_cost / net_amount` | net_amount=0 → — |
| 7日滚动退款率 | `近7日累计退款 / 近7日累计GMV` | 解决大促跨期退款错位 |
| 货品毛利 | `net_amount - cogs - 平台扣点 - 履约成本` | cogs未知时为 — |
| 经营利润 | `货品毛利 - ad_cost` | 扣除买量后最终留存现金 |
| 归因诊断 | LMDI 杜邦三因子增量拆解 | 区分流量/转化/客单价贡献 |

## 二、对比口径

- **环比** = (今日 − 昨日) / 昨日；昨日缺失或为 0 → `—`（不做年同比）
- **周同比** = (今日 − 上周同日) / 上周同日。电商存在强烈的工作日/周末效应，
  日报统一采用**周同比**（7 天前同一星期几），不用年同比
- **比率类指标（退款率 / 转化率）的环比用百分点差值（pp）**：
  退款率从 8% 升到 10% 显示 `+2.0pp`，**不**显示 `+25%`
- ROI 等倍率指标按百分比变化率显示（如 `-25%`）
- 金额内部全程 `Decimal` 计算，仅在展示层转为浮点并保留 2 位小数

## 三、平台口径差异（关键）

| 平台 | GMV 口径 | 含运费 | 含税 | 退款处理 | 实际成交公式 | 数据粒度 |
|---|---|---|---|---|---|---|
| 淘宝/天猫（生意参谋） | 支付（paid） | 否 | 否 | 单独字段扣除 | `gmv - refund_amount` | sku_day |
| 抖音电商（抖店罗盘） | 支付（paid） | 否 | 否 | 单独字段扣除 | `gmv - refund_amount` | sku_day |
| 拼多多（商家后台） | 支付（paid） | 否 | 否 | 单独字段扣除 | `gmv - refund_amount` | sku_day |
| 京东（京东商智） | **下单（ordered）** | **是** | 否 | 单独字段扣除 | `gmv - refund_amount` | sku_day |

> ⚠️ **京东 GMV 含运费且为下单口径，与其他平台不可直接相加比较。**
> 聚合引擎计算"全平台合计 GMV"时照常相加，但结果旁必须带标注 `*京东GMV含运费`
> （Excel 总览口径备注与看板 GMV 卡片 tooltip 均有提示）。

## 四、归一化处理规则

1. **列映射**：按适配器 `column_map` 精确匹配源表头，未命中时尝试 `column_aliases`
   （平台改版容错）；必需列（`stat_date` / `platform_product_code` / `gmv`）缺失 → 整文件失败并给出列名清单
2. **类型转换**：
   - 金额：剥离千分位逗号、`￥/¥`、空格、`元` 等字符；`-` / `--` / 空串 → default；`unit: fen` 自动 ÷100
   - 日期：按 `formats` 顺序尝试（含 `2026-09-06` / `2026/09/06` / `20260906` / 带时分秒），支持 Excel 序列日期（如 45358）
   - 整数：四舍五入（ROUND_HALF_UP），`12.6 → 13`
3. **行过滤**：`row_filters` 全部条件 AND，通过才保留；被剔除的行记 `filtered_out`（不算失败，可查行级明细）
4. **去重**：按 `dedup.keys`（统计日期 + 平台 + 商品编码 + 店铺）分组；重复行按 `sum` 策略合并
   （数值求和、字符串取首个非空），被合并行记 `duplicate_row`
5. **原始快照**：每行保留 `raw_row_json`（原始表头 → 原始字符串值），用于溯源
6. **店铺兜底**：`shop_code` 缺失时用 `shop_name` 兜底，皆缺填 `__UNKNOWN__`

## 五、SKU 跨平台映射

匹配优先级：

1. **查表命中**：`(platform_key, platform_product_code)` 已有人工确认的映射 → 直接沿用
2. **精确码匹配**：平台商品编码恰好等于内部 `sku_code` → 自动映射（confidence=1.0）
3. **名称模糊匹配**：仅生成**建议**，不自动落库。名称预处理（转小写、去除【】[]()（）及其中内容、
   去除 `克/kg/ml/毫升/片/支/盒/袋/装/正品/旗舰/包邮/新款` 等规格词、压缩空格）后，
   用 `token_sort_ratio` 打分：≥90 高置信、75~90 中置信、<75 不建议
4. **未映射**：不丢弃、不阻塞报表。聚合时归入虚拟分组**【待映射】**
   （Excel 分SKU Sheet 末尾标黄 `FFF2CC`；看板显示独立条目并提示"点击去映射"）

## 六、异常预警规则

初始化内置 6 条规则（阈值与 `min_base` 均可在看板调整）：

| 规则 | 指标 | 范围 | 操作符 | 阈值 | 基数下限 |
|---|---|---|---|---|---|
| GMV 环比大幅波动 | gmv_dod | 平台 | abs_gt | 30% | 1000 |
| SKU GMV 环比骤降 | gmv_dod | SKU | lt | -40% | 500 |
| 退款率超限 | refund_rate | SKU | gt | 15% | 500 |
| 整体退款率超限 | refund_rate | 整体 | gt | 20% | 0 |
| 转化率异常下滑 | conversion_rate_dod_pp | 平台 | lt | -2.0pp | 1000 |
| 推广 ROI 过低 | roi | 平台 | lt | 1.0 | 500 |

- `min_base`：主体当日 GMV 低于该值不评估，避免小样本噪音
- `abs_gt`：变化率绝对值超过阈值触发
- 级别：超出阈值 1 倍以内为 `warning`，超过 1 倍为 `critical`

## 七、数据完整性提示

`expected_platforms` 为 4 个内置平台。报告日某平台无任何数据时，
看板顶部橙色横幅与 Excel 总览红底块提示"缺失 N 个平台数据，合计值不完整"，
Excel 口径说明 Sheet 会列出当日实际使用的数据来源文件（上传时间、总行数、有效行数）。

## 八、适配器字段名容错

四个内置适配器的 `column_map` 源表头基于各平台后台常见导出字段名整理。
各平台均已通过 `column_aliases` 配置 2~3 种常见变体（如淘系"支付总额/成交金额"、
拼多多"支付GMV/成团金额"）。若实际导出文件字段名不一致：

1. 打开「适配器管理」页 → 选择平台
2. 在 YAML 编辑器的 `column_map` / `column_aliases` 中补充实际表头名
3. 点击「校验」→ 通过后「保存」→ 重新上传或「重新解析」即可生效
