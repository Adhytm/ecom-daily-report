## 1. 任务背景

原始需求分两阶段：

**第一阶段 · 业务逻辑与产品问题审查**
从「真实商业产品能否正常使用」的角度系统排查：
① 业务闭环完整性（前后端流程闭环、状态流转一致性、接口成功但状态未更新、边界/空数据/重复提交/刷新重进异常）；
② 明显与潜在 Bug（状态管理、异步竞态、重复请求、错误处理缺失、加载/空/失败态不全、校验漏洞、反馈与真实数据不符）；
③ 用户体验设计（该自动化的却要手动、暴露技术细节、步骤冗长、缺反馈/确认/撤销）；
④ 按 P0（核心业务不可用）/ P1（明显影响体验或正确性）/ P2（一般体验）/ P3（可选）分级。

**第二阶段 · 前端提升到商业化产品级**
目标「成熟、可商业化交付」：简洁、克制、有产品设计感、强信息层级，避免「AI Demo」或「后台管理模板」感。
参考 Apple 思路（留白、层级、精细圆角与间距、克制阴影、柔和背景、细腻边框高光、流畅微交互），但不过度堆砌。
约束：不改 API 契约与数据结构、不为重构而重构、不为高级感牺牲可读性、不做廉价科技风。
