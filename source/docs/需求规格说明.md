## 1. 产品目标与边界

### 1.1 目标

电商运营人员每天从多个平台后台手工导出销售数据文件，字段名、统计口径、编码、日期格式各不相同，需要 1~2 小时手工拼接成日报。本工具将该过程压缩到 3 分钟：拖入文件 → 自动识别平台 → 归一化 → 出日报。

### 1.2 MVP 范围内

- 手工上传 CSV / XLSX 文件（支持多文件批量）
- 4 个内置平台适配器：淘宝/天猫、抖店、拼多多、京东
- 适配器 YAML 配置的查看、编辑、校验
- 归一化到统一 Schema 并落库 SQLite
- SKU 跨平台映射（精确 + 模糊建议 + 未映射分组）
- 多维聚合：平台 / 店铺 / 类目 / SKU
- 环比（vs 昨日）、周同比（vs 上周同日）
- 异常预警（规则引擎，阈值可配）
- Excel 日报导出（7 个 Sheet，含样式与条件格式）
- 群发文字摘要生成
- Web 看板
- 内置模拟数据生成器（用于无真实数据时的全链路验证）

### 1.3 明确排除（执行方不得实现）

- ❌ 平台 API 对接、爬虫、自动抓取
- ❌ 账号体系、登录、多租户、权限管理
- ❌ 实时数据刷新、WebSocket
- ❌ 利润核算、库存预测、广告投放分析
- ❌ Docker 化、CI/CD、云服务部署
- ❌ 数据库迁移工具（Alembic）——MVP 阶段用 `create_all` + 版本号重建

## 4. 统一数据模型

### 4.1 统一 Schema（归一化目标字段）

所有字段名固定，执行方不得增删改。数值类型统一用 `Decimal`（ORM 层 `Numeric`），**禁止用 float 存金额**。

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `stat_date` | Date | 否 | 统计日期（已截断到天） |
| `platform_key` | String(32) | 否 | 平台标识，来自适配器 |
| `shop_code` | String(64) | 是 | 店铺编码，无则用 `shop_name` 兜底 |
| `shop_name` | String(128) | 是 | 店铺名称 |
| `platform_product_code` | String(64) | 否 | 平台侧商品/SKU 编码 |
| `product_name` | String(256) | 是 | 平台商品标题 |
| `category` | String(128) | 是 | 类目 |
| `sku_id` | FK→Sku | 是 | 映射后的内部 SKU，未映射为 NULL |
| `order_qty` | Integer | 是 | 下单件数 |
| `paid_qty` | Integer | 是 | 支付件数 |
| `gmv` | Numeric(14,2) | 否 | 支付金额（口径见适配器声明） |
| `refund_amount` | Numeric(14,2) | 是 | 退款金额 |
| `net_amount` | Numeric(14,2) | 否 | 实际成交额，按适配器 `net_amount_formula` 计算 |
| `visitors` | Integer | 是 | 访客数（UV） |
| `buyers` | Integer | 是 | 支付买家数 |
| `ad_cost` | Numeric(14,2) | 是 | 推广花费 |
| `raw_row_json` | JSON | 否 | 原始行完整快照，用于溯源 |

`error_type` 枚举：`missing_required_column` / `date_parse_failed` / `number_parse_failed` / `filtered_out` / `duplicate_row`

**`SalesFact`** —— 归一化后的销售明细（4.1 全部字段 + 下列）

### 4.3 派生指标定义（聚合层计算，不落库）

| 指标 | 公式 | 除零处理 |
|---|---|---|
| 退款率 | `refund_amount / gmv` | gmv=0 → None |
| 客单价 | `net_amount / buyers` | buyers=0 → None |
| 件单价 | `net_amount / paid_qty` | paid_qty=0 → None |
| 转化率 | `buyers / visitors` | visitors=0 → None |
| UV 价值 | `net_amount / visitors` | visitors=0 → None |
| 推广 ROI | `net_amount / ad_cost` | ad_cost=0 → None |
| 推广费比 | `ad_cost / net_amount` | net_amount=0 → None |
| 环比 | `(today - yesterday) / yesterday` | yesterday=0 或 None → None |
| 周同比 | `(today - lastweek_same_weekday) / lastweek_same_weekday` | 同上 |

**重要**：电商日报的"同比"统一采用**周同比（7 天前同一星期几）**，不用年同比。原因是电商存在强烈的工作日/周末效应。文档与 UI 文案均写"周同比"。

比率类指标的环比**用百分点差值（pp）而非百分比变化**，例如退款率从 8% 到 10% 显示 `+2.0pp`，不显示 `+25%`。

## 5. 适配器 YAML 规范

### 5.1 完整 Schema

```yaml
adapter_version: 1
platform_key: doudian                 # snake_case，全局唯一，不得更改
display_name: 抖音电商（抖店罗盘）

file_matching:
  extensions: [.csv, .xlsx]
  encoding_candidates: [utf-8-sig, gb18030, utf-8]   # 按序尝试解码
  header_row: auto                    # 整数(1-based) 或 auto
  auto_header_hints: ["商品ID", "支付金额", "统计时间"]  # auto 时用于定位表头行
  skip_footer: 0
  detect_keywords: ["抖店", "罗盘", "商品ID"]          # 平台自动识别打分用
  detect_weight: 1.0

column_map:                           # 源表头(字符串精确匹配) -> 统一字段名
  "统计时间": stat_date
  "店铺名称": shop_name
  "商品ID": platform_product_code
  "商品名称": product_name
  "一级类目": category
  "支付金额": gmv
  "支付商品件数": paid_qty
  "退款金额": refund_amount
  "商品访客数": visitors
  "支付人数": buyers
  "推广消耗": ad_cost

column_aliases:                       # 可选，源表头的备选写法（平台改版容错）
  gmv: ["成交金额", "支付总额"]
  paid_qty: ["支付件数"]

required_columns: [stat_date, platform_product_code, gmv]
optional_columns: [shop_name, product_name, category, paid_qty,
                   refund_amount, visitors, buyers, ad_cost, order_qty]

transforms:
  stat_date:
    type: datetime
    formats: ["%Y-%m-%d %H:%M:%S", "%Y-%m-%d", "%Y/%m/%d", "%Y%m%d"]
    truncate_to: day
  gmv:
    type: money
    strip_chars: [",", "￥", "¥", " ", "\t", "元"]
    unit: yuan                        # yuan | fen（fen 时自动 /100）
    default: "0"
  refund_amount:
    type: money
    strip_chars: [",", "￥", "¥", " "]
    unit: yuan
    default: "0"
  paid_qty:
    type: integer
    strip_chars: [",", "件"]
    default: "0"
  visitors:
    type: integer
    strip_chars: [","]
    default: null                     # null 表示缺失保持 NULL，不填 0
  platform_product_code:
    type: string
    strip_chars: [" ", "\t", "'"]
    trim: true

metric_semantics:
  gmv_basis: paid                     # paid | ordered | shipped
  gmv_includes_shipping: false
  gmv_includes_tax: false
  refund_handling: separate           # separate | deducted | none
  net_amount_formula: "gmv - refund_amount"
  timezone: Asia/Shanghai
  grain: sku_day                      # sku_day | order_line | day

row_filters:                          # 全部条件 AND，通过才保留
  - column: stat_date
    op: not_null
  - column: gmv
    op: numeric
  - column: product_name
    op: not_contains
    values: ["测试", "赠品"]

dedup:
  enabled: true
  keys: [stat_date, platform_key, platform_product_code, shop_code]
  strategy: sum                       # sum | last | first（grain=sku_day 用 sum）
```

### 5.2 `net_amount_formula` 求值规则

- 只允许引用统一 Schema 的数值字段名与 `+ - * / ( )` 和数字常量
- **禁止使用 `eval`**。实现一个基于 `ast.parse` 的白名单求值器，仅接受 `BinOp / UnaryOp / Num / Name`，`Name` 必须命中白名单字段，否则抛 `AdapterConfigError`
- 当公式引用的字段为 NULL 时，该字段按 `0` 参与计算；但若 `gmv` 为 NULL 则整行判为无效
- `refund_handling: deducted` 时公式应为 `"gmv"`；`none` 时公式为 `"gmv"` 且在口径说明中标注"退款数据缺失，实际成交额未扣除退款"

### 5.3 `op` 支持的操作符

`not_null` / `is_null` / `numeric` / `in` / `not_in` / `contains` / `not_contains` / `gt` / `gte` / `lt` / `lte` / `eq` / `neq`

### 5.4 四个内置适配器的口径设定（关键，不得改）

| 平台 | gmv_basis | 含运费 | refund_handling | net_amount_formula | grain |
|---|---|---|---|---|---|
| taobao | paid | 否 | separate | `gmv - refund_amount` | sku_day |
| doudian | paid | 否 | separate | `gmv - refund_amount` | sku_day |
| pinduoduo | paid | 否 | separate | `gmv - refund_amount` | sku_day |
| jd | ordered | **是** | separate | `gmv - refund_amount` | sku_day |

京东的 `gmv_includes_shipping: true` 必须在 Excel「口径说明」Sheet 与看板 tooltip 中显式提示，因为它导致京东 GMV 与其他平台不可直接相加比较。聚合引擎在计算"全平台合计 GMV"时**照常相加**，但结果旁必须带标注 `*京东含运费`。

## 6. 核心模块设计

### 6.1 `file_parser.py`

职责：把一个上传文件变成 `pandas.DataFrame`（**原始表头，未映射**）。

处理流程：
1. 按字节读取，若扩展名 `.xlsx/.xls` → `openpyxl` 读取（`read_only=True`, `data_only=True`）
2. 若 `.csv` → 按 `encoding_candidates` 顺序尝试解码，用 `charset_normalizer.from_bytes` 作为兜底；全部失败则抛 `FileParseError("无法识别文件编码")`
3. 剥离 BOM、统一换行符为 `\n`
4. 表头定位：
   - `header_row` 为整数 → 直接用
   - `auto` → 扫描前 20 行，取"与 `auto_header_hints` 命中数最多"的行作为表头；命中数为 0 则抛错
5. 表头单元格清洗：`strip()`、去除换行、去除不可见字符（`\u200b` 等）
6. 重复表头名自动加后缀 `_2`、`_3`，并记录到解析日志
7. 全空行丢弃；`skip_footer` 指定的尾部行数丢弃
8. 返回 `(DataFrame, ParseMeta)`，`ParseMeta` 含：`encoding`、`header_row_index`、`detected_columns`、`dropped_empty_rows`、`warnings[]`

**约束**：本模块**完全不知道平台业务字段**，只做物理层解析。所有 `dtype` 保持 `object`/`str`，类型转换是 normalizer 的职责。

### 6.2 `normalizer.py`

职责：`DataFrame(原始)` + `AdapterConfig` → `list[NormalizedRow]` + `list[RowError]`。

流程：
1. **列映射**：按 `column_map` 建反向索引；对未命中的统一字段，尝试 `column_aliases`；仍未命中且属于 `required_columns` → 整个文件失败，抛 `MissingRequiredColumnError`（含缺失列名与文件实际列名清单）
2. **逐行转换**：按 `transforms` 对每个字段执行类型转换
   - `money`：先去 `strip_chars`，空串/`-`/`--` 视为 `default`，再转 `Decimal`；`unit=fen` 则 `/100`；转换失败记 `RowError(number_parse_failed)` 并跳过该行
   - `datetime`：按 `formats` 顺序尝试，Excel 数字序列日期（如 `45358`）需特殊处理；再按 `truncate_to` 截断；失败记 `RowError(date_parse_failed)`
   - `integer`：去 `strip_chars` → `Decimal` → `int()`（**四舍五入而非截断**，用 `ROUND_HALF_UP`）
   - `string`：`strip_chars` + `trim`
3. **口径换算**（`semantics.py`）：计算 `net_amount`；`shop_code` 缺失时用 `shop_name` 兜底，两者皆缺时填 `__UNKNOWN__`
4. **行过滤**：应用 `row_filters`，被过滤的行记 `RowError(filtered_out)`（**不算失败**，只在报告中统计数量）
5. **去重**：按 `dedup.keys` 分组，按 `strategy` 合并；`sum` 策略下数值字段求和、字符串字段取首个非空；被合并的行记 `RowError(duplicate_row)`
6. **原始快照**：每行保留 `raw_row_json`（原始表头 → 原始字符串值，NaN 转 None）

返回 `NormalizeResult`：`rows[]`、`errors[]`、`stats{total, valid, filtered, duplicated, failed}`、`semantics_note`（人类可读的口径说明文本）。

**性能要求**：单文件 5 万行内应在 10 秒内完成。使用 pandas 向量化处理转换，**不要写 Python 逐行 for 循环遍历 DataFrame**（`raw_row_json` 快照可用 `df.to_dict('records')` 批量生成）。

### 6.3 `sku_mapper.py`

职责：为 `NormalizedRow` 填充 `sku_id`，并维护映射表。

匹配优先级：
1. **查表命中**：`(platform_key, platform_product_code)` 在 `SkuMapping` 中且 `sku_id` 非空 → 直接返回，`match_type` 沿用表中值
2. **精确码匹配**：`platform_product_code` 恰好等于某个 `Sku.sku_code` → 自动建立映射，`match_type=exact`，`confidence=1.0`
3. **名称模糊匹配**（仅用于生成**建议**，不自动落库）：
   - 用 `rapidfuzz.process.extractOne`，算法 `token_sort_ratio`
   - 候选池：同 `category` 的全部 `Sku.name`；不足 5 个候选时扩大到全量
   - 预处理：转小写、去除 `【】[]()（）` 及其中内容、去除规格词（`克|kg|ml|毫升|片|支|盒|袋|装|正品|旗舰|包邮|新款`）、压缩连续空格
   - `score >= 90` → 高置信建议；`75 <= score < 90` → 中置信建议；`< 75` → 不建议
4. **未映射**：以上都不命中 → 写入 `SkuMapping(sku_id=NULL, match_type='unmapped', confidence=0)`，行的 `sku_id` 保持 NULL

**未映射行的处理原则（重要）**：绝不丢弃、绝不阻塞报表。聚合时归入虚拟分组 `【待映射】`，在 Excel「分SKU」Sheet 中单独置于末尾并标黄，在看板中显示为独立条目并提示"点击去映射"。

批量接口 `POST /api/sku-mappings/batch` 接受 `[{platform_key, platform_product_code, sku_id}]`，在一个事务内 upsert，`match_type=manual`。

### 6.4 `aggregator.py`

输入：`report_date`、`scope{platforms[], shops[]}`、`compare_enabled`

输出结构（固定契约，前端依赖）：

实现要求：
- 用**单次 SQL 查询**取出 `[report_date-30, report_date]` 的全部 `SalesFact` 到 DataFrame，之后所有维度聚合在 pandas 内完成。**禁止为每个维度单独发 SQL**（N+1）。
- 环比/周同比通过 `df[df.stat_date.isin([d0, d1, d2])]` 分组后 reindex 对齐计算，缺失日期该维度对比值为 `None`。
- 排序：`by_sku.mapped` 按 `net_amount` 降序；`by_platform` 按 `net_amount` 降序。
- 金额输出为 `float`（JSON 序列化需要），但**内部计算全程 `Decimal`**，仅在最终序列化时转换，且 `round(2)`。
- `share` = 该维度 `net_amount` / 总 `net_amount`。

### 6.5 `anomaly.py`

规则引擎，遍历启用的 `AnomalyRule`，对指定 `scope` 的每个主体求值。

`operator` 语义：`gt`（值 > 阈值触发）、`lt`、`abs_gt`（|变化率| > 阈值触发，此时 `metric` 应为 `xxx_dod` 形式）

`min_base` 语义：仅当主体的 `gmv`（或规则指定基准字段）>= `min_base` 时才评估，避免小样本噪音。

**初始化插入的 6 条默认规则**：

| name | metric | scope | operator | threshold | min_base |
|---|---|---|---|---|---|
| GMV 环比大幅波动 | gmv_dod | platform | abs_gt | 0.30 | 1000 |
| SKU GMV 环比骤降 | gmv_dod | sku | lt | -0.40 | 500 |
| 退款率超限 | refund_rate | sku | gt | 0.15 | 500 |
| 整体退款率超限 | refund_rate | overall | gt | 0.20 | 0 |
| 转化率异常下滑 | conversion_rate_dod_pp | platform | lt | -2.0 | 1000 |
| 推广 ROI 过低 | roi | platform | lt | 1.0 | 500 |

`severity` 判定：超出阈值 1 倍以内为 `warning`，超过 1 倍为 `critical`。

### 6.6 `excel_report.py`

用 `openpyxl` 生成 7 个 Sheet，顺序与名称固定：

1. **日报总览** —— 顶部标题行（`{公司名} 电商销售日报 {date} {weekday}`），下方指标表格：`指标 | 今日 | 昨日 | 环比 | 上周同日 | 周同比`。接着是 `data_completeness` 警告块（缺平台时红底）。最后是口径备注。
2. **分平台** —— `平台 | GMV | 占比 | 实际成交 | 退款额 | 退款率 | 件数 | 买家数 | 访客 | 转化率 | 客单价 | 推广费 | ROI | GMV环比 | GMV周同比`
3. **分店铺** —— 同上，首列为 `平台 | 店铺`
4. **分类目** —— `类目 | GMV | 占比 | 实际成交 | 件数 | 件单价 | GMV环比 | GMV周同比`
5. **分SKU** —— `SKU | 商品名 | 类目 | 平台 | GMV | 实际成交 | 件数 | 退款率 | GMV环比`；末尾追加 `【待映射】` 分组，整块底色 `FFF2CC`
6. **异常预警** —— `级别 | 范围 | 对象 | 指标 | 当前值 | 阈值 | 说明`；`critical` 行红底白字，`warning` 行黄底
7. **口径说明** —— 逐条列出：数据来源文件清单（含上传时间、行数、有效行数）、各指标定义、`gmv_basis` / `含运费` / `refund_handling` 的平台差异表、缺失数据说明

**样式规范**：
- 表头：底色 `1F4E79`，字体白色加粗 11pt，居中，行高 24
- 数据行：字体 10pt，隔行底色 `F2F7FB`
- 冻结：所有明细 Sheet 冻结首行 + 首列（`freeze_panes = "B2"`）
- 金额格式：`#,##0.00`；整数：`#,##0`；百分比：`0.0%`；百分点：`+0.0"pp";-0.0"pp"`
- 变化率：正数绿色 `006100` + 前缀 `+`，负数红色 `9C0006`
- 条件格式：环比列 `abs_gt` 阈值命中时整格底色 `FFC7CE`
- 列宽：按内容自适应，上限 40，下限 10；商品名列固定 45
- 自动筛选：明细 Sheet 表头行加 `auto_filter`
- 所有 Sheet 的 `sheet_view.showGridLines = False`

输出路径：`data/exports/daily_report_{YYYYMMDD}_{HHMMSS}.xlsx`，同时更新 `DailyReport.excel_path`。

### 6.7 `text_summary.py`

生成纯文本摘要，模板固定如下（`{}` 为占位，数值按格式规则填充）：

```
【{company}电商销售日报】{date} {weekday}

◆ 整体
GMV {gmv}｜环比 {gmv_dod}｜周同比 {gmv_wow}
实际成交 {net}｜退款率 {refund_rate}｜支付件数 {qty}｜买家数 {buyers}
客单价 {aov}｜转化率 {cvr}｜推广ROI {roi}
{note}

◆ 分平台
{每行: · {平台名} {net}（环比 {dod}）{异常标记}}

◆ TOP3 单品
{每行: {序号}. {商品名截断至20字} {net}（环比 {dod}）}

◆ 需关注
{每条异常一行: · [{级别}] {message}}
{无异常时输出: · 本日无异常预警}

{缺失平台警告，无则省略}
—— 由 电商日报工具 自动生成 {generated_at}
```

格式规则：
- 金额：`¥123,456.78`；>= 10000 时额外提供万元简写 `¥12.35万`（阈值可配 `SUMMARY_USE_WAN=true`）
- 变化率：`+12.3%` / `-4.5%`；为 None 时显示 `—`
- 百分点：`+1.2pp`
- 异常标记：`critical` → `🔴`，`warning` → `⚠️`
- **总长度控制在 800 字符以内**（微信/钉钉群消息友好）。超出时按优先级裁剪：先裁 TOP3 → 再裁分平台只保留前 4 → 最后裁"需关注"只保留 critical

配置项 `company` 来自 `config.py` 的 `COMPANY_NAME`，默认 `"XX"`。

### 6.8 模拟数据生成器 `scripts/gen_mock_data.py`

**这是 P0 的关键交付物**，它必须在没有真实平台文件的情况下产出足够逼真、能触发全部代码路径的数据。

CLI：
```powershell
python -m backend.scripts.gen_mock_data --days 35 --skus 40 --outdir samples/mock
```

生成内容：
- 4 个平台 × 35 天 × 40 SKU 的原始导出文件，**按平台分别输出为各自真实格式的表头与文件名**：
  - `生意参谋_商品效果_20260906.csv`（GBK 编码，表头用淘系真实字段名）
  - `抖店罗盘_商品分析_2026-09-06.csv`（UTF-8-BOM）
  - `拼多多_商品数据_20260906.xlsx`
  - `京东商智_商品分析_20260906.csv`（UTF-8）
- 数据特征必须包含：
  - 周末销量为工作日的 1.4~1.8 倍
  - 每 7 天一个小波动周期，35 天内含 2 次"大促日"（销量 3~5 倍）
  - 每个平台有 3~5 个独占 SKU，20 个跨平台共享 SKU（**但商品名写法不同**，用于验证模糊匹配：淘宝写"XX旗舰店正品"、抖音写"【爆款】XX"、拼多多写"XX 包邮"）
  - 退款率 2%~25% 随机分布，其中 3 个 SKU 故意设 >15% 触发预警
  - 2 个 SKU 在最后 3 天销量骤降 50% 触发预警
  - 1 个平台在最后 1 天故意缺失（验证 `data_completeness`）
- 脏数据注入（每平台每天 1~2 行）：
  - 金额带 `￥` 与千分位逗号
  - 日期混用 `2026-09-06` 与 `2026/09/06`
  - 空值、`-`、`--`
  - 1 行商品名含"测试商品"（验证 `row_filters`）
  - 1 组重复行（验证 `dedup`）
  - 拼多多文件末尾 2 行汇总说明文字（验证 `skip_footer` / 无效行容错）

同时生成 `samples/mock/manifest.json` 记录预期聚合结果的关键数字，供 `smoke_test.py` 做端到端断言（允许 ±0.5% 误差，因为浮点与 Decimal 转换）。

## 7. API 契约

所有路径以 `/api` 为前缀。统一响应包裹：

```json
// 成功
{ "ok": true, "data": {...} }
// 失败
{ "ok": false, "error": {"code": "MISSING_REQUIRED_COLUMN", "message": "人类可读中文说明", "detail": {...}} }
```

错误码枚举：`FILE_PARSE_ERROR` / `ENCODING_ERROR` / `MISSING_REQUIRED_COLUMN` / `ADAPTER_CONFIG_INVALID` / `ADAPTER_NOT_FOUND` / `SKU_NOT_FOUND` / `REPORT_NOT_FOUND` / `NO_DATA_FOR_DATE` / `VALIDATION_ERROR` / `INTERNAL_ERROR`

HTTP 状态码：业务校验失败 `422`，资源不存在 `404`，文件解析失败 `400`，服务端异常 `500`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 返回版本、DB 连通性、内置适配器数量 |
| GET | `/api/adapters` | 列表：`platform_key, display_name, version, is_builtin, enabled, mapped_column_count` |
| GET | `/api/adapters/{key}` | 返回 `yaml_text` + 解析后的结构化对象 + `semantics_note` |

| POST | `/api/adapters/{key}/reset` | 恢复为内置 baseline |

## 8. 前端页面规格

### 8.1 全局

- 布局：左侧固定导航（Element Plus `el-menu`，宽度 200px，可折叠），顶部标题栏显示当前报告日期选择器
- 主题色 `#1F4E79`，与 Excel 表头一致
- 所有金额显示用 `utils/format.js` 的 `formatMoney(v)` → `¥123,456.78`；比率 `formatRate(v)` → `12.3%`；变化 `formatDelta(v, isPP)` → 带 `+/-` 与颜色 class
- `null` / `undefined` 统一显示 `—`

## 10. 测试计划

### 10.1 覆盖率要求

`core/` 与 `exporters/` 行覆盖率 **>= 85%**；`api/` >= 75%；`models/`、`scripts/` 不设硬性要求但必须有冒烟覆盖。

执行：`pytest --cov=backend/app --cov-report=term-missing`

### 10.2 必须覆盖的边界场景清单

**解析层**
- 空文件、只有表头无数据、全部行无效
- GBK / GB18030 / UTF-8 / UTF-8-BOM 四种编码
- 表头在第 3 行（前两行是说明文字）
- 表头含前后空格、换行、`\u200b`
- 重复表头名
- 文件末尾汇总行
- 超过 50MB 的文件被拒

**归一化层**
- 金额：`"1,234.56"` / `"￥1234"` / `"-"` / `"--"` / `""` / `"0.00"` / 负数 / 科学计数法字符串
- `unit: fen` 的除以 100
- 日期：4 种格式 + Excel 序列号 + 含时分秒需截断 + 非法日期
- 整数：`"1,234"` / `"12件"` / `"12.6"`（应四舍五入为 13）
- `required_columns` 缺失
- `column_aliases` 生效
- `net_amount_formula` 中字段为 NULL
- 公式注入攻击被拒
- `row_filters` 全部 13 种操作符
- `dedup` 三种策略

**映射层**
- 完全无匹配
- 模糊匹配得分恰好 75 / 89.9 / 90 的边界
- 同 `platform_product_code` 在不同平台映射到不同 SKU
- 批量映射部分失败回滚

**聚合层**
- 单日无数据、连续多日缺失
- 昨日为 0（环比应为 None，不能除零）
- 上周同日为 0
- 只有 1 个平台有数据（`data_completeness` 警告）
- 全部 SKU 未映射
- 退款额 > GMV（异常数据，应正常计算不崩溃，退款率 > 100%）

**导出层**
- 0 条异常时「异常预警」Sheet 显示"本日无异常"
- 商品名超长（> 100 字符）不破坏列宽
- 中文文件名下载头编码
- 摘要超长三级裁剪

**API 层**
- 全部错误码各有 1 个测试触发
- 重复 `generate` 幂等
- 上传非 CSV/XLSX 文件被拒

`scripts/smoke_test.py` 见 T14 验收标准。它是**最终交付的唯一硬性门槛**。
