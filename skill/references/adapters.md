# 多平台电商适配器与口径对照表

本参考文档供 AI Agent 查阅，用于在做数据核对、口径解释或新适配器编写时对照使用。

---

## 1. 平台覆盖与内置适配器

系统内置 4 大主流电商平台的原始导出表格适配器，全部通过 YAML 规则表达：

| 平台名称 | 适配器 Key | 常见导出渠道 | 文件特征 |
| :--- | :--- | :--- | :--- |
| **淘宝 / 天猫** | `taobao` | 生意参谋 - 商品效果 | CSV，GBK 编码，表头含 `商品名称`、`商品ID`、`支付金额` |
| **抖音电商** | `doudian` | 抖店罗盘 - 商品分析 | CSV / XLSX，UTF-8 编码，表头含 `成交金额`、`退款金额`、`商品名称` |
| **拼多多** | `pinduoduo` | 商家后台 - 商品数据 | XLSX，表头含 `商品成交金额`、`商家实收金额`、`成团订单数` |
| **京东** | `jd` | 京东商智 - 商品分析 | CSV，表头含 `下单金额`、`成交金额`、`SKU`（注意：下单金额通常含运费） |

---

## 2. 字段映射与净销售额（Net Amount）公式

所有平台表格解析后，归一化到统一的 14 个核心物理指标：

1. `gmv` (下单成交额)
2. `net_amount` (实际成交/净销售额)
3. `refund_amount` (退款金额)
4. `paid_qty` (支付件数)
5. `buyers` (支付买家数)
6. `visitors` (商品访客数 / UV)
7. `ad_cost` (推广花费)
8. `cost_price` (货品成本价)
9. 各平台特有字段通过 `net_amount_formula` 统一求值：
   - 白名单 AST 计算，禁止 `eval`。
   - 示例：`paid_amount - refund_amount` 或 `settle_amount`。

## 3. 平台口径风险与特殊处理

- **京东含运费**：京东商智的成交额通常包含用户支付的运费，系统在统计报表和摘要中会主动标注 `*京东（京东商智）GMV含运费`，避免与无运费口径混淆。
- **脏数据容错**：
  - 自动剥离货币符号（`¥`、`$`、`￥`）与千分位逗号（`1,234.50`）。
  - 自动跳过尾部的“数据说明”、“生成时间”等非数据行。
  - 自动识别多级表头与日期混用格式（如 `2026/09/06` 与 `2026-09-06`）。
